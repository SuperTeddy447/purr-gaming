## Spatial decision

Chosen model: **C — Mochi leaves through the left-side counter passage and approaches the seated customer.** A (behind-counter handoff) left Mochi far from seated customers, while B (fixed front-counter position) still left a substantial gap to Seats B/C/D. The old ServePoint was inside the CounterFront visual footprint (x195–735, y435–632). The new `counter_serve_01` marker remains the stable semantic ID but sits at (100,785) as an open-floor service-lane waypoint; the final service position is the active seat's authored `ServiceApproach` marker. The tap target follows that active approach.

Worker: WorkerIdle (620,445) → CoffeeAction (402,445) → CounterExitRear (165,445) → CounterExitFront (165,700) → ServePoint (100,785) → seat-specific approach → reverse waypoints → WorkerIdle. Seats B/D also pass WorkerFloorAisle (165,1050); Seat C additionally passes RightAisle (700,1050). The existing `SliceMover` follows every point; no teleport, navigation system, or character z-index override was added.

Customer: CustomerSpawn/Exit (426,1506) ↔ CustomerEntry (350,1370) ↔ CustomerAisle (235,1080) ↔ assigned seat. Seat C additionally uses RightAisle to avoid crossing Table 2. Seat A remains (225,915); B moved to (445,1230), C to (638,1260), and D to the available right side of Table 1 at (360,935). Seat D still has no dedicated chair in the locked furniture layout.

The left passage between the side wall panel (ending x152) and CounterFront (starting x185) is only about 33 world pixels wide at the floor pivot. The cat artwork visually overlaps the panel edge while passing; this is **not** proven collision-clear for future final art and requires a human playtest/level decision. No architecture was moved to hide it. The debug route view is intentionally busy but disappears entirely when debug is OFF.
