# WilliCat provider provenance policy V1 — hardened draft

Research/production-gate policy, **not legal advice** and not a grant to import any third-party pack. The [provider research report](../research/WILLICAT_ASSET_PROVIDER_PRODUCTION_BEST_PRACTICES_RESEARCH_V1.md) remains the evidence record. This document uses the canonical `rights` gate and use-scope outcomes from the [manifest schema](../architecture/WILLICAT_ASSET_MANIFEST_SCHEMA_V1_DRAFT.md); the [ecosystem standard](../architecture/WILLICAT_ASSET_ECOSYSTEM_STANDARD_V1_DRAFT.md) controls environment promotion.

## Exact-package intake and use-scope assessment

Record provider/creator, pack title, acquisition URL/date/tier, archive name/hash, version or `unknown`, local source path, official product page and capture date, included LICENSE/TERMS/README reference/hash, permitted/restricted uses, attribution, AI conditions, reviewer role and timestamp. Keep the original evidence reference and any conflict; do not copy third-party raw art into research documents. A current product page does not silently override terms for an unidentified older download. `LICENSE / PROVENANCE UNRESOLVED` is an evidence status, never permission.

Each requested use receives its own `scope_assessment`: `scope`, `outcome`, `evidence_refs`, `notes`. Canonical scopes: `structural_study`, `dev_runtime`, `production_runtime`, `modification`, `raw_redistribution`, `generative_conditioning_reference`, `ai_training`, `publication_distribution`. Outcomes: `permitted`, `prohibited`, `unresolved`, `not_applicable`. An `unresolved` or `prohibited` outcome blocks that specific use. A permitted study or DEV proof does not imply permission for production, redistribution or AI conditioning. The `rights` gate can be `passed` only for the scopes required by the next environment/transition; a gate result is contextual, not a blanket license boolean. `V-PROVENANCE` checks the requested scopes and emits a rights review record.

Existing temporary proxies whose release scope is unverified remain **DEV-only** as an operational environment restriction, not a fifth rights outcome. Keep them isolated/excluded from release/source distribution until separately reviewed. Finished game builds/screenshots and extractable raw source files may have different permissions. Never redistribute third-party standalone files or repackage them as a WilliCat library unless exact terms explicitly permit it. CC0 on a different archive does not establish rights for the local copy.

## First-party generated source trace

Every future first-party source records request/spec version, approved `template_id`/`template_version`, referenced `world_authority_ref` and revision/hash (or UI layout authority), `style_family_id`/calibration evidence, creator/tool/date, all input rights assessments, source file hashes, rejected revisions/reasons, normalized export hashes, `source_asset_version`, optional `supersedes` and final human review record. When authority geometry changes, dependent template/source versions are identified as potentially stale through the documented `invalidation_relationship`; logic is specified but not implemented here. Provider production grammar may inform technical templates without using copyrighted pixels or recognizable visual identity as generative conditioning. A generated output is not automatically approved merely because it is first-party.

No release pack, new art, Mini Pack 002 or Asset Factory generation is authorized by this policy.
