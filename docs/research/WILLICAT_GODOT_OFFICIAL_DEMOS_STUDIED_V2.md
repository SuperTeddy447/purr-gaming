# Official Godot demo study V2

Source: [Godot 4.7 demo release `6ad6167`](https://github.com/godotengine/godot-demo-projects/releases/tag/6ad6167), studied as source scenes/scripts, not just screenshots or summaries. Some demos are narrow proofs, not production templates.

| Exact official demo file | Structure/code observed | Architectural lesson for WilliCat |
| --- | --- | --- |
| [`2d/isometric/dungeon.tscn`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/isometric/dungeon.tscn) | `Floor` and `Walls` use `y_sort_enabled`; TileMapLayer is nested in the corresponding depth group. Repeated decorations are scene instances. The readme describes base colliders and vertical tile offsets. | Floor-contact origins and correct local sort groups matter more than changing character z-index by state. Even an isometric world can mix map cells with reusable scenes. |
| [`2d/navigation/navigation.tscn`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/navigation/navigation.tscn) | Level owns `NavigationRegion2D` and a NavigationPolygon resource; it instances `character.tscn` and includes a Camera2D. | Walkable space is level data; character movement can remain reusable. |
| [`2d/navigation/character.tscn`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/navigation/character.tscn) + [`character.gd`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/navigation/character.gd) | CharacterBody2D root owns Sprite2D, CollisionShape2D, NavigationAgent2D. Script assigns target_position and calls get_next_path_position + move_and_slide in physics processing. | Separate destination selection from locomotion. Agent finds a path but does not drive the body itself. |
| [`2d/navigation_astar/pathfind_astar.gd`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/navigation_astar/pathfind_astar.gd) | TileMapLayer script configures AStarGrid2D bounds/cell size/Manhattan/no diagonals; tile cells become solid points. | AStarGrid2D is excellent when cells are the actual walkability authority, not merely because the artwork looks isometric. |
| [`2d/instancing/ball.tscn`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/instancing/ball.tscn) + [`scene_instancing.tscn`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/instancing/scene_instancing.tscn) + [`ball_factory.gd`](https://github.com/godotengine/godot-demo-projects/blob/6ad6167/2d/instancing/ball_factory.gd) | Ball scene bundles sprite/collision; parent scene places many instances at distinct coordinates; factory instantiates a PackedScene dynamically. | A reusable object carries its internals, while a world/level owns instance placement. This is the key pattern for chair, bed, plant, station. |

The [official 2D navigation overview](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_introduction_2d.html) directly links the navigation and AStarGrid demos. The [official scene-instancing guide](https://docs.godotengine.org/en/stable/getting_started/step_by_step/instancing.html) describes per-instance overrides; the demos show that arrangement concretely. None of these demos should be copied wholesale into a café game.
