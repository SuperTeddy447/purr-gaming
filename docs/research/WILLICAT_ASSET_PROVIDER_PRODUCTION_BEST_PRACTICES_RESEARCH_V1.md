# WilliCat asset provider production best practices research V1

Research audit, 2026-09-30. **No art, runtime scene, world coordinate, navigation, or gameplay change is authorized by this report.** Home's current Café → Plaza → Riverside → Garden route is spatial authority. Mini Pack 001 is evidence of a successful technical swap and an unsuccessful visual acceptance. This study concerns production grammar, not a style lock; neither deep jade nor a proposed Japanese countryside palette is approved here.

**Evidence labels:** **O** observed in named local file/screenshot; **M** measured from local pixels/metadata; **D** documented by creator or WilliCat record; **I** inference requiring verification; **P** proposed WilliCat rule. Official links describe the page checked on this date, not a license certificate for an unidentified local download. No third-party raw art was copied to this report or to the repository by this task.

**Hardening terminology note (PROPOSED):** This report remains an evidence/autopsy record. Its historical phrases `technical_pass` and `visual_pass` are not separate writable gate IDs. The canonical gates are `rights`, `structural`, `motion`, `visual`, `runtime`, `human`; canonical category, lifecycle and scoped-rights vocabularies are defined in the [hardened manifest](../architecture/WILLICAT_ASSET_MANIFEST_SCHEMA_V1_DRAFT.md). `production_ready` remains derived. Provider observations and the ten research rules below are unchanged.

## Provider mechanics worth transferring

### Tiny Swords: terrain, depth, authored motion, FX and UI

- **D** The [creator's tilemap guide](https://pixelfrog-assets.itch.io/tiny-swords/devlog/1138989/tilemap-guide) defines background → foam → flat ground → repeated shadow/elevated ground layers. It distinguishes flat edges, elevated top, cliffs to water or lower walkable terrain, stairs and foam. Shadow and foam overhang more than one logical tile; foam phases should vary. **M** local `Shadow.png` is **192×192**, while the guide text says 128×128; this is a documented/local-version dimensional discrepancy, not a reason to guess slicing. Source asset dimensions must win for a specific import.
- **O/M** `Tree1.png` contains eight fixed 192×256 canvases. Alpha area across frames is 11,139–11,173 pixels (~0.3% range) and the bottom 24-pixel contact crop has the same `(72,0)–(125,9)` bounds in all frames. The visible upper silhouette shifts subtly while ground contact holds. The Aseprite source timeline has 36 frames at 100 ms, but its mapping to the exported eight-frame strips was not decoded. The product page's 100 ms claim **does not prove asymmetric authored timing**. **I** its convincing sway comes from frame-specific foliage shape/position and stable base, not a whole-sprite scale transform; acceleration, holds and overshoot require temporal review, not merely counting frames.
- **O/D** Bushes, 16-frame water-rock strips, clouds, 16-frame foam, separate shadows and composited dust/fire/splash/explosion families make ambient and one-shot motion reusable. The [product page](https://pixelfrog-assets.itch.io/tiny-swords) explicitly describes combining two dusts, three fires and two explosions. WilliCat should borrow compositing roles, not combat intensity.
- **O/D** UI includes regular/pressed buttons, independent bar base/fill, slot sheets, panels/ribbons, icons and cursors; product page calls out stretchable surfaces. Dynamic bar values belong in the fill/mask layer, not a baked panel image.

### LimeZu: a catalog that can grow

**D** The [creator page](https://limezu.itch.io/moderninteriors) organizes files by size and theme, supplies per-theme tilesets plus a global sheet, individual furniture PNGs, three export sizes, character generator and RPG Maker instructions. Its [maintenance logs](https://limezu.itch.io/moderninteriors/devlog) discuss compatibility and repaired singles. **I/P** WilliCat should keep stable family IDs, projections, scale rules, named object variants and versioned exports. Theme and resolution are *orthogonal filters*, so one new room family need not relabel existing objects. A searchable preview should show each object in the same camera and against a human-scale actor. The exact LimeZu archive taxonomy and source editability remain unverified without a local package.

### SuperRetroWorld: separate the five axes

**M/O** In local `Characters/Farm`, each 48×80 walk export is 3 columns × 4 rows of 16×20 frames; each 96×128 action export is 3×4 of 32×32 frames. Visual inspection shows rows represent distinct facing views and columns progress the action; the *exact row-to-compass map is undocumented locally* and must be confirmed before import. `farm_walk_01` and `_04` are distinct looks/character variants, while `walk`, `hoe`, `shovel`, `watering` are actions. Door image orientation differs across files. Godot tile animation durations are explicit in the `.tres`. **P** A manifest must separately declare character/variant, action, state, direction and ordered timeline; never derive semantics solely from suffixes or dimensions. The local AI-training restriction bars using the pixels as generative conditioning.

### Kenney and KayKit: predictable intake and reusable foundations

**D** Kenney exposes tile size, file count, version and CC0 on [Tiny Town](https://kenney.nl/assets/tiny-town), and UI family size/version on [UI Pack](https://kenney.nl/assets/ui-pack). **P** WilliCat's package root should state those facts, source/export separation and manifest revision so import requires no guessing. `tilemap.txt` was not found locally and is **not** a verified Kenney convention in this study.

**D** KayKit's [modular Dungeon Pack](https://kaylousberg.itch.io/kaykit-dungeon-pack) reuses one gradient atlas across many modules, offers interchangeability and publishes format fixes. **P** In WilliCat 2D, transfer common connector measurements, family palette/material rules and shared atlas budgeting. Do **not** impose 3D FBX/glTF, mesh draw-call advice or gradient materials on illustrated sprites without 2D profiling.

**Frame count ≠ motion quality.** Frame count checks missing cells and clip duration; motion QA checks readable rest, directional canopy travel, easing/hold/return/overshoot/settle when appropriate, silhouette volume, trunk contact, loop seam and scene-level perception. Tiny Swords' eight-frame source and equal documented 100 ms rhythm show that frame-specific drawing can succeed without claiming its timing is asymmetric. The Mini Pack's four frames can be technically valid and still fail the human motion gate.

## Open questions for human review

1. What first-party camera/projection and style-family calibration reference will be approved before any further production? This research does not choose one.
2. What measured connector module sizes and door aperture dimensions correspond to the existing Home geometry? Derive from world authority; do not change it.
3. What accepted first-party motion examples will calibrate tree root/area/centroid tolerances and per-frame timing?
4. Which exact local third-party download/version and acquisition records apply, especially Gif, Cozy Coffee, FreeAssets, Frog and Penzilla? Resolve before release use or any generative workflow.
5. Which Kenney/KayKit/LimeZu archive conventions can be verified if a licensed package is later acquired? Current page-level study does not prove inner file details.

# TEN RULES WILLiCAT MUST NOT BREAK

1. Freeze Home geometry and semantic world data before specifying art; artwork must fit those measurements.
2. Approve a category template with floor baseline, pivot, canvas and footprint before generating an asset.
3. Build architecture as connected modules with exact join and door-aperture contracts; a gap between PNGs is not a doorway.
4. Require complete terrain adjacency, including edges and corners, before a terrain family enters the world.
5. Keep source frames, normalized exports, runtime prefabs and review previews separately traceable.
6. Encode direction, action, state, variant and timeline explicitly; never infer them from filename suffix or sheet dimensions alone.
7. Lock ground contact and author motion as a readable arc; frame count and fixed canvas alone do not approve animation.
8. Use visual children/prefabs to preserve gameplay roots, seats, nav, save IDs and world transforms.
9. Stop any failed asset before production runtime integration; technical PASS and human visual PASS are separate mandatory gates.
10. Record provenance and exact rights for every input; borrow provider production grammar while keeping WilliCat art original.
